While the project is in beta, versions are `v0.MINOR.PATCH` and the `0` major makes no compatibility promise. Versions derive from conventional commits on first-parent history of `main`: a `feat` bumps MINOR and resets PATCH, a `fix` bumps PATCH; other types do not change the version. Tags are sparse checkpoints, made only when the user asks, and the tag equals the derived version (so tags usually skip numbers): `git tag -a v0.X.Y -m "v0.X.Y"`.
