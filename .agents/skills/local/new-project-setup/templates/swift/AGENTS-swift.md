- Xcode folders are synced groups: create a new file on disk in the right folder and leave `project.pbxproj` alone.
- A new Swift file starts with Xcode's header: `//`, `//  <FileName>.swift`, `//  {{APP}}`, `//`, `//  Created by {{AUTHOR}} on <dd/MM/yyyy>.`, `//`.
- App code is grouped by layer (`App/`, `DomainModels/`, `Networking/`, `Repositories/`, `ViewModels/`, `ViewStates/`, `Views/`); a folder appears with its first file. Tests mirror it with a `Tests` suffix (`Networking/` → `NetworkingTests/`). Shared test helpers live in `{{APP}}Tests/Fixtures/`: test-only extensions on app types in `Extensions.swift`, anything else in its own file.
- View models vs view states: `ViewModels/` holds `@Observable` classes with behaviour (user actions, async, injected dependencies), named `...ViewModel` and tested as the user's actions in order. `ViewStates/` holds plain structs derived from a view model's state, named after the view they feed (`CurrencyRow` → `CurrencyRowState`) and tested as pure input → output. Text that needs a locale is a method taking `locale:`, which the view calls with `@Environment(\.locale)`, so view models never hold a locale. Test: if it changes something, awaits or holds a dependency, it's a view model; if the same input always gives the same output, it's a view state.
- Types that cross async or closure boundaries (models, clients, repositories, dependencies) declare `nonisolated` and `: Sendable` explicitly, even where the compiler would infer it, so a non-`Sendable` field fails at the definition.
- Prefer `if` expressions to the ternary operator.
- SwiftFormat owns layout and SwiftLint checks the rest: run `./scripts/format.sh`, then `./scripts/lint.sh`, before each commit. Code over a size or complexity limit says why in a `swiftlint:disable` comment.
- Tests use Swift Testing (`@Test`, `#expect`, `#require`) and read as the user's actions on screen, in order. User-facing text goes in `Localizable.xcstrings`.
- Tests target `{{SIMULATOR}}`. The user runs them in Xcode; run them from the CLI only when the user asks, since `xcodebuild` can be slow or hang: `xcodebuild test -project {{APP}}.xcodeproj -scheme {{APP}} -destination 'platform=iOS Simulator,name={{SIMULATOR}}'` (add `-only-testing:{{APP}}Tests/<Suite>` for one suite). `./scripts/coverage.sh` reports app coverage, overall and without the UI.
