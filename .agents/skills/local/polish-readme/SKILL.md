---
name: polish-readme
description: Polish a project README's first screen and intro so it is accurate and easy to scan. Use when the user asks to polish, tidy or redo a README.
---

- **Scan, then read.** The intro is one line per feature, a bold lead and a short clause, linking to its section; details go in `<details>` sections below. Keep the hand-written table of contents in step with the sections.
- **Badges that stay true:** CI, latest release, license, language version, and the platforms the project actually runs on. Each one updates itself.
- **Screenshots in a grid:** a table whose shape fits the number of shots (rows of two or three, not one long strip), every image cropped to the same aspect ratio. Stage realistic data so pages look in use. A visible UI bug gets fixed in the product, not painted over in the image.
- **Exact claims.** Describe what a feature really does and scope each warning to the feature that carries the risk, next to it. Check every claim against the code.
- **Quick Start is one copy-paste block,** optional steps as commented lines. Move legacy paths to the end instead of the main flow.
- **No personal setup:** host and machine names, private IPs, VPN details, in text and in screenshots.
- **Finish with a done-against-asked list** for the user to review.
